# 两个新机制的设计稿：**共振（S 旋钮）** 与 **兑换窗口（铸币新职能）**

> 状态：**仅设计，未动代码** ✓
> 新意判据（本稿所有机制都要先过它）：
> **这个机制是否让玩家做一个 AD 里不存在的决定？** 若只是"更深/更快/更贵" ⇒ 那是 AD 的形状 ✗。

---

## 0. 一句话

```
共振　= 把我们**内部的数学不变量 S**（环增益红线）变成玩家手里的**风险旋钮** ✓
兑换窗口 = 把铸币从"又一个 IP 乘数" ✗ 改成"**什么时候把手里的量子兑现**" ✓（最优停止问题）

两者咬合 ⇒ 产生一个 AD 里不存在的两难：
   共振越猛 ⇒ 量子涨得越快 ⇒ 兑换窗口的收益越高 ✓
   但共振越猛 ⇒ S 越贴近红线 ⇒ 崩落风险越大 ✗
   ⇒ 玩家必须在"更进一步"与"见好就收"之间**连续下注** ✓✓
```

## 1. 共振：把 S 从护栏变成赌注

### 1.1 现状（它现在只是代码里的护栏 ✗）

```
S = Σ log(mᵢ) / log(rᵢ)        （环增益，见 computeS ✓ 与 docs/R-REPLACEMENT.md ✓）
   · 判据：S < 1 ⇒ 环收敛 ✓；S ≥ 1 ⇒ 环发散（历史上"物质一次跳无限"的旧 bug ✗）
   · 当前值：S ≈ 0.7263（基础）✓；人际关系加成叠乘 ^1.002×^1.005×^1.015 = ^1.0221
     ⇒ S_eff ≈ 0.7423 ✓（离红线还有 ~0.26 的余量 ✓）
   · 玩家**完全看不到它** ✗ —— 这是我们最独特的一份数学资产，却藏着不用 ✗
```

### 1.2 玩法化：共振模式

```
新增开关「共振」（解锁：某个里程碑 ✓）：
   · 开启后，**环的产出倍率**按 S 放大 ✓（S 越高越猛 ✓）
   · 同时 S 的**实际值会被推高**（因为放大本身进了环 ✓）
   · 一旦 S_eff ≥ 1 ⇒ **崩落**：本轮环相关的积累清零 + 一段冷却 ✓（不是死机，是重罚 ✓）
   · 随时可「退共振」⇒ S 立刻回落到基础值 ✓（安全 ✓）
```

### 1.3 数学（回报与风险各自的形式）

```
回报（环产出倍率）：   R(S) = 1 / (1 − S)^p         p ≈ 0.5~1（S→1 时暴涨 ✓）
    ⚠️ 必须**硬上限**（数值安全 ✗）：R ≤ R_max（例如 1e6 ✓），超出部分走阈值软上限 ✓

推进（S 自身怎么涨）： S(t) = S₀ + Σ(共振期间新增的环项) ✓
    ⇒ 玩家每次"再推一格"都会让 S 更高 ⇒ 回报更高 ✓ 但余量更小 ✗

崩落的判定（**确定性**，为了可测 ✓）：S_eff ≥ 1 的**那一帧**立即崩落 ✓
    ⇒ 不是随机概率 ✗（随机不可测 ✗ 也难以写断言 ✗）
    ⇒ 张力来自：**玩家不知道确切余量**（S 的每一项随他的操作变化 ✓）

余量可见化（UI）：只显示"距离红线还有多少"的**宽带条**（不显示精确值 ✓）
    ⇒ 既给了信息 ✓ 又保留了"看不清"的紧张感 ✓✓
```

### 1.4 玩家做什么决定

```
① 要不要开共振（开 ⇒ 更快但进赌局 ✓）
② 推到多猛（每推一格，回报上升、余量下降 ✗）
③ **什么时候退**（退太早 ⇒ 少赚 ✓；退太晚 ⇒ 崩落 ⇒ 本轮清零 ✗✗）
⇒ 这是一个**连续时机的风险管理** ✓ —— AD 里不存在 ✓✓（AD 的软上限都是被动护栏 ✗，玩家从不下注 ✓）
```

### 1.5 落点与红线（按项目规矩）

| 项 | 落点 | 说明 |
|---|---|---|
| 共振的回报倍率 | **ZPE 乘区**（熵阱 ↔ ZPE 这条环本身 ✓） | 共振就是"把环推过临界"✓ ⇒ 落点必须在环上 ✓ |
| ❌ 不许 | 全局加成 ❌ | "只有真·全局的东西才进全局位" ✓ |
| ❌ 不许 | 让 S 的计算绕开 `computeS` ❌ | 单一数据源 ✓（显示与实发必须同一函数 ✓） |

### 1.6 需要的新断言（tools/）

```
· 共振关闭时，一切与现在**逐位一致** ✓（零回归 ✓）
· 回报 R(S) 与引擎实发一致（显示 == 实发 ✓）
· R 有硬上限（无论 S 多大都不越界 ✓）
· S_eff ≥ 1 **必然且仅**触发一次崩落 ✓（不重复触发 ✓ 冷却期不再触发 ✓）
· 退共振后 S 立即回到基础值 ✓
· 崩落的代价是**本轮**清零，不碰跨轮资产 ✓（存档安全 ✓）
```

## 2. 兑换窗口：铸币的新职能

### 2.1 现状（它是"又一个乘数" ✗）

```
铸币等级 → coinageMult → 直接乘进 IP 收益 ✗
⇒ 与 ipDouble（余额→收益 ✗）职能重叠 ⇒ 玩家看不出区别 ✗（这正是你问"能不能取消"的原因 ✓）
```

### 2.2 新职能：把**本轮量子**按**随时间衰减**的汇率兑现成 IP

```
ΔIP = ∫₀^τ rate(t) · q'(t) dt
   · q(t)  = 本轮已捕获的量子（本轮归零 ✓ 天然是"每轮重来"的资源 ✓）
   · rate(t) = 汇率，**随本轮时间衰减** ✓：rate(t) = r₀ · 2^(−t/T)（T = 半衰期 ✓）
   · τ = 玩家**选择**的兑现时刻 ✓（不选 ⇒ 大坍缩时自动按 τ = 轮末兑现 ✓）
```

### 2.3 数学：这一步的最优解（这就是玩法的骨头 ✓）

```
最大化 IP(τ) = ∫₀^τ r₀·2^(−t/T)·q'(t) dt
   ⇒ 极值条件：**rate(τ)·q'(τ) = 0** 的边界解 ⇒ 实质是"边际汇率损失 = 边际量子收益" ✓
   ⇒ 对 rate 的指数衰减：最优 τ* 满足   q'(τ*)/q(τ*) = ln2 / T
        （即：**量子增长率的相对速度** 追平 **汇率的衰减速度** 时收手 ✓）

关键性质（决定手感）：
   · 本轮前期 q 增长慢 ⇒ 早收不划算 ✓
   · 本轮后期 q 增长快（ZPE 已经起飞 ✓）⇒ 晚收赚 ✓，但汇率已经掉了很多 ✗
   · ⇒ τ* 落在"q 开始指数增长之后、汇率还没掉到底之前" ✓ ⇒ **玩家可感知的窗口** ✓✓
   · rate 必须有**地板**（rate(t) ≥ r₀·floor ✓，例如 0.2 ✓）⇒ 晚收永不归零 ✓（不然玩家会怕到不敢晚收 ✗）
```

### 2.4 玩家做什么决定

```
① 什么时候兑现（早 vs 晚 ⇒ 汇率 vs 量子量的取舍 ✓）
② 兑现后要不要**继续跑**等更多量子（第二轮窗口？✗ 一个轮次只有一个窗口 ✓ 更干净 ✓）
③ 与共振配合：共振开着 ⇒ q 涨得更快 ⇒ τ* 提前 ✓（玩家要重新找窗口 ✓✓）
⇒ 「在一条衰减曲线上找最优点」—— AD 里不存在 ✓✓
```

### 2.5 落点、合并与红线

| 项 | 决定 |
|---|---|
| 落点乘区 | **IP（∞ 层）** ✓（产出的是无限点 ✓，与 `ipFromQuantum` 同类 ✓） |
| 与 `ipFromQuantum` 的合并 | **合并成一个入口** ✓（两者都吃量子 ⇒ 合并才"职能唯一" ✓ —— 见 `COINAGE-TIER-ROLES.md` §6 的问题2 ✓） |
| 与档位的关系 | 档位只留 `tierAccel`（节奏脊柱 ✓）；铸币的**等级上限**改由"兑换额"自然约束 ✓（不再用 30×坍缩次数 ✗） |
| ❌ 不许 | 接进全局加成 ❌；用指数形式（`×2^等级` ✗）⇒ 判据红线 ✓ |

### 2.6 需要的新断言

```
· rate(t) 的衰减与地板：显示 == 实发 ✓
· 最优 τ* 与解析解一致（数值积分 vs 闭式 ✓）
· 兑现总额**有上界**（多项式安全 ✓，不随轮长指数增长 ✓）
· 大坍缩时未兑现的部分**按轮末汇率**结算 ✓（不丢失玩家资产 ✓）
· 与 `ipFromQuantum` 合并后**只有一条** IP-量子路径 ✓
```

## 3. 两者咬合：这才是我们要的"新意"

```
共振 ↑ ⇒ 环产出 ↑ ⇒ ZPE ↑ ⇒ 量子捕获 ↑ ⇒ 兑换窗口的 q 涨得更快 ✓
共振 ↑ ⇒ S ↑ ⇒ 崩落风险 ↑ ✗
⇒ 玩家每时每刻都在做同一道题：**"再猛一点，还是现在兑现收手？"** ✓✓

而且两者的"最优策略"都**不是**"一直推到顶" ✗ ——
   共振有崩落红线 ✗；兑换有汇率衰减 ✗
⇒ 游戏从"挂机等数字"变成"**管理一条越来越陡的曲线**" ✓
⇒ 这是 AD（以及绝大多数增量游戏）没有的形状 ✓✓
```

✗ 不新增第四种货币
✗ 不在上线前动这两者（先上线，再单独开一轮 ✓）
