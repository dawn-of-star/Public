## 0. 为什么是"累计量子对数"，而不是"当前量子个数"

- 当前量子数 `q` **每次大坍缩归零**（与量子对数一起重置）⇒ 键在它上面的里程碑
  只会在第一轮全部拿完，之后形同虚设 ✗
- **累计量子对数**（历史总量）**永不清零** ⇒ 它是量子层的"永久进度标尺" ✓
- 这条教训是照抄 AD 的：`break-infinity-upgrades.js` 里
  `totalAMMult` 用 `player.records.totalAntimatter`（累计），`currentAMMult` 用当前值 ——
  **被硬顶/被重置的量要给永久收益，必须走累计量**（见 `PROGRESSION.md` §0.4 手法③）。

> ✅ **已核实（2025）**：`state.quantumPairsTotal`（累计对数）**已经存在**
> —— `state.js:168` 定义、`engine.js:313` 累加、`engine.js:756` 明确写着
> "`quantumPairsTotal` 是累计统计量，保留"（即**大坍缩不清零**）✓
> 所以本设计**不需要新增 state 字段**，直接键在它上面即可。

## 1. 草案：7 条（阈值按 ~×2.4 递进）

| # | id | 需要（累计对数） | 效果 | 它在解决什么 |
|---|---|---|---|---|

| 2 | `qm2` | 3 | **档位加速开启**：每档位 `b` ×**1.0209** | ★ **这就是 24 档合计能从 321h 压到 ~90h 的那个来源** |
| 3 | `qm3` | 8 | `b` ×1.10 | 前段提速 |

> ⚠️ **`qm2` 的系数是 1.0209，不是 1.06** —— 这是我**手算错的**一个数，被数值反解纠正：
> `1.06^24 = 4.05` ⇒ 24 档只花 62.6h（比 ×1.75 标尺快 1.44×）✗；
> 反解 **1.0209** ⇒ 正好 89.86h ✓。断言已把它钉住（`quantum-particle-lab` §④）。

**设计意图（一句话）**：1~3、6 给**速度**，2 给**阶梯形状**，4 给**引擎段**，5 给**反馈**，7 给**跨度**。

## 2. 阶梯算术（证明它们能把 24 档压到 ×1.75 的目标）

```
已知：起点跃迁 1e200 ⇒ 单档只需跨 108 阶（不是 308）
目标：打破无限 → 永恒 = AD WR 51.35h × 1.75 = 89.86 h（24 档）
设档位加速 ×g/档 ⇒ 每档耗时 = 108 / (b₁·g^(i−1))
  Σ ≈ (108/b₁) · (1 − g^−24)/(1 − 1/g)
取 g = 1.06 ⇒ 系数 = (1 − 1.06^−24)/(1 − 1/1.06) = 0.7555/0.0566 = 13.35
令 Σ = 89.86h = 323,496 s ⇒ b₁ = 108 × 13.35 / 323,496 = **0.00446 阶/秒**
```

⇒ **`g = 1.0209`**（**不是** 1.06 —— 见 §1 的警示），而 `b₁ ≈ 0.0064`（含 qm1 ×1.10）
与模型反解出的 `b0 = 0.003755`（乘上首轮倍率后 = 0.0064）**完全一致** ✓
说明"档位 ×1.0209 + `b0 = 0.003755`"这一组参数是自洽的 ✓

## 3. 与既有系统的边界（不改既有规矩）

| 规矩 | 本设计如何遵守 |
|---|---|
| **只给"落点唯一"的加成上色** | 7 条的效果分别落在：粒子（`b`）、暗能量（`a`、`k`）、量子门槛（步长）⇒ 落点明确，可登记乘区 |
| **单一数据源** | `b` 与 `k` 都只在一个函数里汇总（`bMultiplier(state)` / `matterSpanExponent(state)`），引擎与界面共用 |
| **影响永恒阶段 ⇒ 必须有极强软上限** | `b` 封顶 0.02 阶/秒；`k` 仍受 6.1651 硬封顶；`a` 的倍率封顶 |
| **不进环** | 粒子在环外（实测 `effectiveTraps` 不读粒子）；`a`/`k` 落在 ZPE→DE→物质 的输出侧 |
| **玩家不失去已有进度** | 里程碑**永久**（键在累计量上，永不归零）✓ 即便"永恒"重置一切（除梦想系统），里程碑是否保留**需要你定**（见 §4） |
