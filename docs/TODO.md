## I. 机制重设计：**「最快无限时间」驱动量子加成**（用户方案，待实现）

**用户原话**：「基于**最快的一次无限时间**，使量子的加成指数提升（最快 1s 无限，数值怎么设计显而易见）」

### I1. 为什么它现在才有意义
H1 改完之后，`k↑` ⇒ 更快 ⇒ `T_best` 更小 ⇒ 加成更高 ⇒ **正反馈**，但被 `runSeconds` 钉住 ⇒ **不发散** ✓
（改 H1 之前：`k↑` 反而让收手更早 ⇒ 方向相反 ✗）

### I2. 形状（数据已算出）

```
加成 = (T_ref / T_best)^p        T_best = 历史最快无限时长（秒），T_ref = 参考时长
```
| 实测事实 | 数值 |
|---|---|
| 每轮收入 ∝ 时长上限^**4.4**（1s → 1e3.8；60s → 1e28.8）| 跨度 **1e25** |
| **每小时**收入：1s ⇒ 1e3.08｜60s ⇒ 1e4.57 | **60s 反而强 30 倍** ⇒ **现在没有理由追快** ✗ |
| 盈亏平衡（让 1s 与 60s 的每小时收入相等）| **p ≈ 0.41** |

⇒ **`p` 的取值就是"最快 1 秒值多少"**：`p=0.5` ⇒ 1s 比 60s 强约 ×4。

### I3. ⚠️ 必须先解决的前提（否则机制不成立）
```
「追最快」要让玩家**赚**，就必须让"浅但快"的轮次在**每小时收入**上 ≥ "深但慢"的轮次。
而现在数值是**相反的**（60s 强 30 倍）⇒ 光加一个加成可能不够，需同时确认：
   · 是走"加成补偿"（p 调大）还是走"深度收益本身也变"（改 IP 公式的除数）
```
